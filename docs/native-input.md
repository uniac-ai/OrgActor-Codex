# Native questions in Forms

The Actor's current canonical manager answers an ordinary standalone Form once. Labels show question text and choice descriptions. Opaque field names seal the original native request payload; native question IDs and protocol envelopes stay private. The Actor/session/thread/turn/request, reviewed fields, applied inputs and designated respondent must still match before a typed answer attempt is saved and sent.

| Native input                                  | Form projection                                                         | Native result                                                                                                                                                       |
| --------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Question with options                         | One choice field using the option labels                                | Selected label in a one-element answer array.                                                                                                                       |
| Question without options, including `isOther` | One free-text field                                                     | Ordinary text in a one-element answer array.                                                                                                                        |
| Options plus `isOther`                        | Distinct Other choice plus optional plain-text Other field              | One custom answer when Other is selected. Native options named Other retain their own meaning. Conflicting selections require revision.                             |
| No value supplied for a question              | The respondent submits the optional field without a value               | Empty native answer array. The native schema declares no multi-select flag or answer-count limits; this scalar projection produces zero or one answer per question. |
| Optional MCP plain string or boolean          | Plain text or Yes/No choice                                             | Typed string or boolean. Defaults are never inserted as respondent answers.                                                                                         |
| Optional MCP single-choice enum               | Display titles when supplied, otherwise values                          | The selected native value.                                                                                                                                          |
| Representable MCP request decision            | Required Accept/Decline/Cancel choice, followed by optional data fields | Accept submits typed content; Decline/Cancel submit the corresponding native action with null content and metadata, ignoring supplied data.                         |

Flat MCP objects in `form`, `openai/form` or `openaiForm` mode use the installed MCP SDK's restricted primitive contract. Raw constraints must survive that parse, including constraints nested inside enum choices. Only the native form envelope's documented nullable Option fields normalize null to absence. Arbitrary-schema aliases retain every raw key/value. Unsupported or stripped constraints stop projection with the concrete field path. The original supported schema, including its declared dialect, validates the converted content before any answer attempt.

Optional MCP fields preserve absent values and explicitly empty plain text. Optional boolean and enum values may be omitted; any supplied value must be a displayed choice. Enum display-title and native-value counts must match before a Form is created, and every selected option must resolve to a real native value. The public Form validates its required decision and choice values before recording a Human response; rejected input stays awaiting that Human. Accept alone can submit no data and produces an empty content object. Form closure or requester cancellation is not an elicitation response.

MCP schemas with any required properties remain pending: the public Form cannot require values only for Accept while allowing Decline and Cancel without them. Numbers/integers, string formats, positive minimum lengths, and maximum lengths below the Form's 20,000-character answer limit also remain pending before Form creation. A plain string may explicitly allow a zero minimum or a maximum at least as large as that limit. These constraints cannot be implemented solely by labels and private rejection: a Hub-valid response would leave the Human's awaiting list without a public correction path. The Provider adds no correction-Form lifecycle or validation engine. The SDK's final native validation remains a private guard for Accept; Decline and Cancel do not validate content.

Secret input cannot preserve privacy in organization-readable Forms. URL flows, nested/open schemas, multi-select fields and constraints outside the typed flat contract remain pending for native-owner recovery. The same applies when a projection exceeds Workspace's actual limits: 100 fields (including the MCP decision), 100 choices per field, and 20,000 characters per label/value. These are Form limits, not invented native question-count limits. The console reports the unsupported path or limit and does not direct the operator to a nonexistent Form. Existing native-owner controls remain the recovery surface; the Provider adds no input bypass or schema interpreter.

The private `answerAttempt` is saved before the native socket write. Its outcome stays unconfirmed because the transport has no correlated answer acknowledgement. Forms remain open, and unknown attempts are never replayed. A returned canonical Form ID remains in its same retained binding after resolution, turn completion or controller close; replacement bindings are untouched. See [private migration and recovery](workspace-migration.md).
