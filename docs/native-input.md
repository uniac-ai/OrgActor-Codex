# Native questions in approval asks

Every Hub-owned native request becomes an approval ask, so only the Actor's managers answer it, once, and the first answer resolves it. A permission prompt's title names the command or grant, its context holds the reason and requested scope, and one decision field offers Approve, Decline or Cancel, each with a detail. A native question's title is its question; an MCP request's title is its message. Labels show question text, and choices carry their descriptions as option details. Opaque field names seal the original native request payload; native question IDs and protocol envelopes stay private. The Actor/session/thread/turn/request, reviewed fields and applied inputs must still match before a typed answer attempt is saved and sent.

| Native input                                  | Ask projection                                                          | Native result                                                                                                                                                       |
| --------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Question with options and `isOther=false`     | One choice field: option labels as values, descriptions as details      | Selected label in a one-element answer array.                                                                                                                       |
| Question without options, including `isOther` | One free-text field                                                     | Ordinary text in a one-element answer array.                                                                                                                        |
| Options plus `isOther=true`                   | One free-text field with option labels/descriptions as guidance         | The present string, whether a choice label or custom text, in a one-element answer array. Explicit empty text is one empty string; absence yields an empty array.   |
| No value supplied for a question              | The respondent submits the optional field without a value               | Empty native answer array. The native schema declares no multi-select flag or answer-count limits; this scalar projection produces zero or one answer per question. |
| Optional MCP plain string or boolean          | Plain text or Yes/No choice                                             | Typed string or boolean. Defaults are never inserted as respondent answers.                                                                                         |
| Optional MCP single-choice enum               | Display titles when supplied, otherwise values                          | The selected native value.                                                                                                                                          |
| Representable MCP request decision            | Required Accept/Decline/Cancel choice, followed by optional data fields | Accept submits typed content; Decline/Cancel submit the corresponding native action with null content and metadata, ignoring supplied data.                         |

Flat MCP objects in `form`, `openai/form` or `openaiForm` mode use the installed MCP SDK's restricted primitive contract. Raw constraints must survive that parse, including constraints nested inside enum choices. Only the native form envelope's documented nullable Option fields normalize null to absence. Arbitrary-schema aliases retain every raw key/value. Unsupported or stripped constraints stop projection with the concrete field path. The original supported schema, including its declared dialect, validates the converted content before any answer attempt.

Optional MCP fields preserve absent values and explicitly empty plain text. Optional boolean and enum values may be omitted; any supplied value must be a displayed choice. Enum display-title and native-value counts must match before an ask is created, and every selected option must resolve to a real native value. The public ask validates its required decision and choice values before recording a manager's answer; rejected input leaves the ask open. Accept alone can submit no data and produces an empty content object. Closing or cancelling the ask is not an elicitation response.

MCP schemas with any required properties remain pending: the public ask cannot require values only for Accept while allowing Decline and Cancel without them. Numbers/integers, string formats, positive minimum lengths, and maximum lengths below the ask's 20,000-character answer limit also remain pending before an ask is created. A plain string may explicitly allow a zero minimum or a maximum at least as large as that limit. These constraints cannot be implemented solely by labels and private rejection: a Hub-valid answer resolves the ask, leaving no public correction path. The Provider adds no correction-ask lifecycle or validation engine. The SDK's final native validation remains a private guard for Accept; Decline and Cancel do not validate content.

Secret input cannot preserve privacy in organization-readable asks. URL flows, nested/open schemas, multi-select fields and constraints outside the typed flat contract remain pending for native-owner recovery. The same applies when a projection exceeds Workspace's actual limits: 100 fields (including the MCP decision), 100 choices per field, and 20,000 characters per label/value. These are ask limits, not invented native question-count limits. The console reports the unsupported path or limit and does not direct the operator to a nonexistent ask. Existing native-owner controls remain the recovery surface; the Provider adds no input bypass or schema interpreter.

The private `answerAttempt` is saved before the native socket write. Its outcome stays unconfirmed because the transport has no correlated answer acknowledgement, and unknown attempts are never replayed. A returned ask ID remains in its same retained binding after resolution, turn completion or controller close; replacement bindings are untouched. See [delivery and recovery](recovery.md).
