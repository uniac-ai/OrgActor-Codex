# Native questions in Forms

The Actor's current canonical manager answers an ordinary standalone Form once. Labels show question text, choice descriptions and useful value constraints. Opaque field names seal the original native request payload; native question IDs and protocol envelopes stay private. The Actor/session/thread/turn/request, reviewed fields, applied inputs and designated respondent must still match before a typed answer attempt is saved and sent.

| Native input                                  | Form projection                                                          | Native result                                                                                                                                                       |
| --------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Question with options                         | One choice field using the option labels                                 | Selected label in a one-element answer array.                                                                                                                       |
| Question without options, including `isOther` | One free-text field                                                      | Ordinary text in a one-element answer array.                                                                                                                        |
| Options plus `isOther`                        | Distinct Other choice plus optional plain-text Other field               | One custom answer when Other is selected. Native options named Other retain their own meaning. Conflicting selections require revision.                             |
| No value supplied for a question              | The respondent submits the optional field without a value                | Empty native answer array. The native schema declares no multi-select flag or answer-count limits; this scalar projection produces zero or one answer per question. |
| MCP string, boolean, number or integer        | Plain text, Yes/No choice or numeric text with the requested constraints | Typed string, boolean or finite number; integers must be safe integers. Defaults are never inserted as respondent answers.                                          |
| MCP single-choice enum                        | Display titles when supplied, otherwise values                           | The selected native value.                                                                                                                                          |

Flat MCP objects in `form`, `openai/form` or `openaiForm` mode use the installed MCP SDK's restricted primitive contract. Raw constraints must survive that parse, including constraints nested inside enum choices. Only the native form envelope's documented nullable Option fields normalize null to absence. Arbitrary-schema aliases retain every raw key/value. Unsupported or stripped constraints stop projection with the concrete field path. The original supported schema, including its declared dialect, validates the converted content before any answer attempt.

Optional MCP fields preserve absent values and explicitly empty text when the native string permits it. Ordinary blank optional numeric, choice and constrained-string inputs are omitted rather than converted to zero or an invalid value. Required formatted strings remain required. A required unformatted string that permits empty text uses an optional Form field with an explicit presence instruction, then native validation enforces the required property. A present empty respondent response is answered; it is not interpreted as a missing response. Enum display-title and native-value counts must match before a Form is created, and every selected option must resolve to a real native value.

Secret input cannot preserve privacy in organization-readable Forms. URL flows, nested/open schemas, multi-select fields and constraints outside the typed flat contract remain pending for native-owner recovery. The same applies when a projection exceeds Workspace's actual limits: 100 fields, 100 choices per field, and 20,000 characters per label/value. These are Form limits, not invented native question-count limits. The console reports the unsupported path or limit and does not direct the operator to a nonexistent Form. Existing native-owner controls remain the recovery surface; the Provider adds no input bypass or schema interpreter.

The private `answerAttempt` is saved before the native socket write. Its outcome stays unconfirmed because the transport has no correlated answer acknowledgement. Forms remain open, and unknown attempts are never replayed. A returned canonical Form ID remains in its same retained binding after resolution, turn completion or controller close; replacement bindings are untouched. See [private migration and recovery](workspace-migration.md).
